# 試作 cable-bench.html の要点と、Rack 側の置き場所

試作（約 50KB）を毎回読まないためのメモ。2026-10-24、段階 B〜F を入れたときに書いた。数値は仕様 `CABLE_PHYSICS_SPEC.md` と同じ。
ただし **曲げ・ケーブル同士の摩擦・止まったかの判定は、仕様から変えた**（下の「仕様から変えたこと」）。試作 `cable-bench.html` も同じに直してあるので、試作と C++ は今も全点一致する。

## 仕様から変えたこと（2026-10-24、ユーザーの返事「A で進めましょう」）

実機の写真（張りのある弧のまま浮いている）に比べて、垂れすぎた。原因は仕様 3.1 の曲げ（点 i と i+2・i+3 の距離を保つ）：
まっすぐに近いゆるい曲がりには力がほとんど出ない（弦の長さは角度の 2 乗でしか縮まない）ので、重力を本物の 5% にしても垂れていた。

| | 仕様（変える前） | いま |
|---|---|---|
| 曲げ | 距離 `i, i+2`（`kb`）と `i, i+3`（`kb*0.55`）、`kb = 0.003 + 0.3*stiff^2.5` | 点 i を点 i-s と i+s の**真ん中からのずれ**に保つ（`solveBend`）。s = 1, 2, 4、強さ `kb * {1, 1/4, 1/16}`、`kb = 0.01 + 0.99*stiff^2`。ずれは曲率に比例するので、ゆるい曲がりにも逆らう。s = 2, 4 があると全体が一度に曲がり、早く落ち着く（s = 1 だけだと長いケーブルが 1600 フレーム這い続けた） |
| クセ | 曲げの静止長（距離）を寄せる | 静止のずれ `restH[s][i]` を寄せる（挿したとき：まっすぐ 0 から初期形のずれへ `mem*0.8`、手で曲げたとき：今のずれへ。率は同じ） |
| 重さの既定 | 22%（重力 49 cm/s²） | 50%（227 cm/s²） |
| ケーブル同士 | 押し離すだけ | **摩擦**（`P.fric`／`settings::cableFriction`、既定 50%）。接点で互いの滑り（法線に直交する分）を、0.04×摩擦 cm 未満なら止め、それ以上なら 0.7×摩擦 だけ減らす（50% でパネルと同じ数字）。サブステップの**最後の衝突の回だけ**（毎回だと接点が細かく震える） |
| 止まったか | 最後のサブステップの移動 < 0.004 cm が 12 フレーム | **1 フレーム全体の移動** < 0.004 cm が 12 フレーム（摩擦のある接点がその場で数 µm 震えても止まれる） |

- 落ち着き方は `python3 reference/physics_check/check_physics.py --settle [硬さ 重さ 摩擦]` で測る。既定（0.9・0.5・0.5）：挿して 100 フレームで固定、
  もう一度起こしても 0.05 cm しか動かない。硬さ 0.5 だと 0.8 cm 動く（柔らかいほど落ち着くのに時間がかかる）。
- 硬いケーブルはパネルから手前に大きく張り出す（長いもので 15〜17 cm）。真正面の画面では影でしか分からない（影は高さで薄くなる）。

## 物理（`src/app/CablePhysics.cpp`、Rack に依存しない）

| 試作 | C++ | メモ |
|---|---|---|
| `makeCable` | `makeCable()` | 初期の弧（上向きの輪／下向き）、二分法 60 回、クセ `mem*0.8` |
| `chooseLength` の自動 | `chooseLength()` | `距離*1.1 + 2*LB + 3` 以上の最短。届かない判定 `tooShort()` は `距離 + 2*LB + 1.5` |
| `rebuildObstacles` | `World::rebuildObstacles()` | `parts`（ノブ等）→ ブーツの順。格子 2cm |
| `step` / `solveBend` | `World::step()` / `solveBend()` | サブ 2・反復 16、距離 → 曲げ（s = 1, 2, 4）、4 反復ごとに ケーブル同士 → 静的。最後にクセ（`plast`） |
| `frame` の中身 | `World::frame()` | ドラッグ中 1 ステップ、ほかは 4。フレーム全体の移動で `still > 12` か 100 フレームで固定 |
| `wake` | `World::wake()` | 寝ていたら速度ゼロ（`prev = 今`） |
| `collideStatic` / `rub` | `collideStatic()` | 机は `Params::desk`（Rack では切ってある）。**同じジャックに挿さった他のブーツも自分のと同じく端 3 点は無視**（試作に重ね挿しは無い） |
| `collideCables` / `segPush` | `collideCables()` / `segPush()` | 格子 1.2cm。**Map の挿入順を `shCells` で再現**（結果が順番に依る）。押し離したあと摩擦（`frictionPass` のときだけ） |
| `applyDrag`、pointerdown/up | `startDrag` / `moveDrag` / `endDrag` | 掴んだ点を `w = 0`、離すと `wake(100)` |

- 試作と全点が一致する（`python3 reference/physics_check/check_physics.py`、差 0）。物理を変えたら必ず回す。**試作の `frame()` を変えたら `bench.js` の `frameSim` も同じに**。
- 試作の `Math.hypot` は 3 引数。Rack は C++11 なので `hypot3()` を自前で持つ。

## Rack につなぐ部分（`src/app/CableRig.cpp`）

- `Rig` が CableWidget ごとに `Entry`（物理のケーブル・描画用の点・パッチから読んだ JSON）を持つ。`RackWidget::step()` から 1 フレーム 1 回。
- ジャック A = 出力側、B = 入力側。cm = Rack の px / 29.528。
- 挿していないプラグ（手で持っている間）は、物理なしで「挿した瞬間の弧」をマウスまで毎フレーム作り直して描くだけ。
- モジュールが動いたら固定点を動かして起こす。届かなくなったら標準の長さで作り直す。
- パッチに保存するもの：`"physics": {"length", "unit": 1e-4, "points": [x,y,z…], "bend": [[s=1 の restH], [s=2], [s=4]]}`（整数、µm）。
  曲げを変える前の形式（`rest2`・`rest3`）は読まずに、挿した瞬間の形から作り直す。
- パネルの部品（仕様 5.1）：`ModuleWidget::getParams()` / `getPorts()` から。ノブ 1.6〜2.2cm（直径 0.6→2.7cm で直線）、
  `SliderKnob` 0.5cm、ほかの param（スイッチ・ボタン）1.0cm、ジャック 0.3cm。3.5cm を超える param（表示・タッチ面）は無視。
- 起こすのは：新しく作ったケーブル、モジュールが動いた、ケーブルが消えた、設定が変わった（ただし前のフレームから寝ていたケーブルがあるときだけ）。
  **パッチから読んだケーブルは起こさない**（保存したときの形のまま。読み直しても差 0 を確かめた）。

## 描画（`CableRig.cpp` の後半、数字は `Look`）

- 試作 `densify` → `densify()`：3D で 1 回 1:2:1 → Catmull-Rom 5 分割。光の向きのずらし `o = n (n・L)`。
- **透視（2026-10-24、ユーザーの案）**：試作はカメラ 0° でも透視がある（ケースの中心の正面 58 cm にカメラ、端のブーツが筒に見える）。Rack も同じにした（`Camera`）。
  ケースは Rack の格子の原点（パッチの pos [0, 0]）から `settings::caseWidth` HP × `caseHeight` U（既定 104HP・6U）、カメラはその中心の正面 `cameraDistance` cm（既定 58）。
  点 (x, y, z) は中心から `D / (D - z)` 倍に広がって写る。**z = 0（パネル）は動かない**ので、モジュール・ポートの位置と操作はそのまま。
  ケーブルとブーツだけが写る位置がずれるので、ブーツ（根元〜先端の筒）の上の押下はそのポートへ回す（`Rig::plugAt`、`RackWidget::onButton`）。
  途中を掴むときは、掴んだ点の高さでマウスを逆に写す（`Camera::unproject`）。影は z = 0 に落とすので変わらない。太さはケーブルごとの平均の倍率。
  View → Cable physics → Perspective で切ると、前の真正面（平行投影、ブーツは先端の円だけ）。
- ブーツ：横の面（フラットは本体を黒へ 10%、立体はケーブルと同じ帯を根元→先端に）、両側の縁、リブ 3 本（0.66・0.78・0.9）、先端の面。試作の `drawBoot` と同じ。
- フラット：10 点ずつの区間をブーツと一緒に z の低い順。区間の継ぎ目は butt（真横に切る）で、本体だけ 1px（`Look::seam`）次の区間へはみ出す。
  ケーブル自身の両端だけ丸く（円を足す）。**試作の「本体を前後 3 点はみ出す」はやめた**（2026-10-24）：はみ出しが、奥行きで間に挟まる別のケーブルの上に描かれ、
  交差でケーブルがめり込んで見えた（ユーザーがスマホで見つけた）。試作 HTML も同じに直した（`FLAT_SEAM`）。
- 立体：ケーブル 1 本を区間に分けず 5 本の線で連続に描き、平均 z で並べる（仕様 4.4）。自分のブーツより下になるときはブーツを先に描く。
  試作も 2026-10-24 から同じ描き方（前は区間ごとに帯の形でクリップしていて、クリップの縁に細い継ぎ目の線が出た。ユーザーがスマホで見つけた）。
- 立体のブーツ：~~試作の 4 段の放射グラデーションを、NanoVG の 2 色グラデーション 3 枚で近似~~ →
  **2026-10-25 から試作と違う**（ユーザー「シェーディング・ヘッドの形・リアリティをもう少しだけ詰めたい、いまの立体風は残したい」）：
  ブーツを回転体（`Look::profile`：胴 → 面取りした肩 → ストレインリリーフ、リブ 3 本は `reliefRibs`）にし、根元から順に、隣の 2 つの輪の外接線で囲んだ形（`hull`）を塗る。
  横を向いた部分はケーブルと同じ 5 本の帯を軸に沿って（光の向きから軸方向の分を除いた向きへずらす）、正面を向いた肩は帯を輪に巻いて（光の側に明るい三日月）。
  肩の光の側に小さなハイライト（`shine`）、外側に暗い縁。真正面では同心の輪、透視の端では筒に見える。
- 立体のケーブル：帯 0 と 1 の間、暗い側に照り返しの細い線（`rimWidth` ほか）。ケーブルが光の向きに沿う所では帯 1 の下に隠れる。
- 影：ブーツは根元から影の点まで、ケーブルは 10 点ずつ butt で、高さで薄く・太く。立体は 2.2 倍・0.35 倍をもう 1 本。
  2026-10-25：ブーツの根元に暗い輪（`contactReach`・`contactAlpha`）。
- **ケーブルに落ちる影**（2026-10-25）：上のケーブルとブーツの影を、下のケーブルの上に描く（`castShadows` → `Entry::cast`、点ごとの濃さ）。
  受ける点から光の向きに上の線までの距離で濃さを決め、高さの差で薄く・縁をぼかす（`castAlpha`・`castSoft`・`castSpread`）。
  立体はケーブル 1 本ずつ平均 z で描くので、**後に描くケーブルだけが前に描いたものへ影を落とす**（局所の高さが逆でも、少なくとも乗っている高さとして）。
  そうしないと、上に描かれたケーブルに下のケーブルの影が乗る。ケーブルが動いたとき（`version`）・カメラ・影の設定が変わったときだけ計算し直す。
  描くのはケーブルの中心線に沿った黒（太さはケーブルと同じ、1 区間ずつ濃さを線形に変える）。ブーツの先端の面には落とさない（NanoVG で円に切り抜けないため）。
- `settings::cableOpacity`（半透明）は物理のケーブルには効かない（重ねた線が透けて汚くなるため）。
